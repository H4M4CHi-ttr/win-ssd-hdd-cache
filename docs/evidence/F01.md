Date: 2026-11-02. Scope: host-only mathematical ranges; no driver/device I/O.

## Environment and reproduction

- rustc 1.99.1 (58cf8f9c3 2026-10-13), x86_64-unknown-linux-gnu.
- Edition 2024, exact toolchain pin, tested minimum declared as 1.99.1.
- No third-party crates. Cargo.lock is committed. Package publication is disabled while GOV01 is unresolved.
- Linux executed. Windows commands are the same but were **not run** at this point; Windows CI is tracked by F10, not hardware qualification.

```sh
cargo test -p cache-types --test range_contract --locked
cargo test --locked
cargo fmt --all -- --check
cargo clippy --all-targets --locked -- -D warnings
```

## Results

The 11 integration tests initially failed at explicit unimplemented function stubs (exit 101). After implementation, 11/11 passed. fmt and clippy passed. Empty library/doc-test suites are not counted as coverage.

The tests cover half-open ranges, empty EOF, error precedence, overflow, cross-line writes, exact alignment, every supported line size, and u64::MAX. Tests use literal expectations independent of the implementation.

Checked arithmetic is a prerequisite for INV-03 range handling, covered only at the pure helper level. INV-09 kernel work/IRQL/resource budgets remain unverified. This does not establish sector alignment, Windows memory ownership, cache coherence, or device safety. No Windows, DMA, signing or hardware operation was performed.

Independent review and final commit/PR references are recorded in Issue #5. No performance claim is made.
