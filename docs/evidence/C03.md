# C03 — Explicit public diagnostics allowlist

2026-11-02, Rust 1.99.1 on x86_64-unknown-linux-gnu. Root observed four diagnostics tests fail at the unimplemented function, then implemented strict parse followed by explicit copies into a separately owned type. All four passed, as did the full 55-test host suite, fmt and clippy.

```sh
cargo test -p cache-types --test diagnostics_allowlist --locked --offline
cargo test --locked --offline
cargo fmt --all -- --check
cargo clippy --all-targets --locked --offline -- -D warnings
```

The public type has only fixed enums and optional u64 counters. It stores no source string, identifiers, arbitrary messages, serde Value or raw parser errors. Rejected path/user/serial/content/nested sentinel values do not appear in Debug/Display errors. Successful results survive dropping the source string. Existing strict missing-field/duplicate/size guards remain in force. No regex sanitization, logging, persistence, CLI command, device/service access or privilege operation was introduced.

This is an offline payload allowlist, not proof that every future logging/telemetry path is private. Live-service privacy remains D06; independent Astra review and PR are recorded on Issue #21. Windows execution and product security qualification are not claimed here.
