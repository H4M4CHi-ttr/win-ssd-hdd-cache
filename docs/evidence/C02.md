# C02 — Offline status CLI

2026-11-02. Root observed eight `status_cli` integration tests fail against renderer/main stubs, then implemented fixed output and strict argument/file handling. On Rust 1.99.1 x86_64-unknown-linux-gnu, all eight passed, along with 63 total applicable host tests, fmt and clippy. Cargo.lock adds only the local cache-cli package; registry package versions did not change.

```sh
cargo test -p cache-cli --test status_cli --locked --offline
cargo test --locked --offline
cargo fmt --all -- --check
cargo clippy --all-targets --locked --offline -- -D warnings
```

Coverage includes all seven states in exact JSON/text golden output, fixed error descriptions, null versus zero, both flag orders, duplicate/missing/unknown arguments, fixed exit/error codes, size/UTF-8/schema failures, spaces/Unicode and Unix non-UTF8 paths, directories, missing paths, and final-component symlink rejection. A Windows-only **pure lexical** namespace test is included but was not executed on this Linux host; it does not open device paths.

The renderer is an allowed C02 supporting change in cache-types; the shared bounded reader supports only unprivileged offline CLI commands. Its explicit filesystem/race limits are documented in [the example guide](../../examples/status/README.md). No network protocol, raw disk API, service, driver installation, elevated process or GUI was added. Windows runtime execution remains F10; independent SOL review/PR belongs to Issue #22.
