# F04 — In-memory origin with unknown bytes

2026-11-02, Rust 1.99.1 x86_64-unknown-linux-gnu. Pure host memory only.

Seven integration tests first failed at the explicit constructor stub. After implementation, 7/7 passed; the full suite passed 27 tests, with fmt and clippy successful.

```sh
cargo test -p cache-model --test origin_contract --locked
cargo test --locked
cargo fmt --all -- --check
cargo clippy --all-targets --locked -- -D warnings
```

Cases: initial known bytes and independent read copies; exact two-byte write across 4095/4096; invalid mutation leaves bytes and known-map unchanged; discard returns UnknownRange, not zeros; partial rewrite restores only touched bytes; zero-length on unknown/EOF and empty capacity; overflowing ranges; exact 1 MiB capacity and rejection above it.

This supplies a byte-level building block for T03/T11. It deliberately models neither concurrency nor volatile/flush/power-loss durability. No physical TRIM, storage, Windows API, threads or timing was used. Unknown bytes may remain internally allocated; this is not secure erasure. Windows host execution is tracked by F10 and is not claimed here. Review/PR references are recorded in Issue #12.
