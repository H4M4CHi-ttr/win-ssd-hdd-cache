# F06 — deterministic host replay and independent oracle

Date: 2026-11-03 JST. Task: [#20](https://github.com/H4M4CHi-ttr/win-ssd-hdd-cache/issues/20).

This is a bounded, single-process **host model**, not the product cache engine, a Windows driver, a DMA emulator or hardware qualification. HDD is the only authority; cache entries are disposable and never write back. The F06 source passed independent review and awaits two-OS PR CI at the checkpoint below. Issue acceptance is recorded only after those gates.

## Reproducible commands

From the repository root with its pinned toolchain and lockfile:

```sh
cargo test --locked -p cache-types --test evidence_format
cargo test --locked -p cache-model --test replay_contract
cargo test --locked -p cache-model --lib oracle::tests
cargo test --locked -p cache-model --test replay_cli
cargo run --locked -p cache-model --example replay -- --trace tests/fixtures/replay/origin-read.json
cargo run --locked -p cache-model --example replay -- --trace tests/fixtures/replay/early-ack.json --fault early_ack
cargo run --locked -p cache-model --bin cache-replay -- --trace tests/fixtures/replay/pending.json
```

The last two commands intentionally return **3** and **2**, respectively. They are not shell success examples. The same early-ACK fixture without `--fault` returns 0 after its actual completion and later commit. Both entry points use one implementation; the binary target permits process-level tests without launching nested Cargo builds from tests. `cargo run` itself may write build messages to stderr; the executable writes only one LF-terminated evidence JSON document to stdout.

| Exit | Meaning | Stdout |
|---|---|---|
| 0 | This trace passed its observed checks | Evidence JSON |
| 2 | Inconclusive: pending work or no meaningful independent observation | Evidence JSON |
| 3 | Semantic/backend/safety/assertion failure, including a correctly detected mutant | Evidence JSON |
| 1 | Usage, input/IO/parser or report/output error | No fabricated replay report on input/parser failure |

The only options are required `--trace <ordinary-file>` and optional `--fault none|stale_fill|early_ack|late_slot_reuse`, each at most once. There is no stdin, automatic device selection, network source, raw-disk mode, privilege elevation or implicit default file. Paths and input bytes are not echoed by errors. The F05 parser supplies its fixed code and optional event index. Existing final symlinks, special files and directories are refused; Windows device/UNC namespaces and DOS device names are rejected before opening. The reader caps input at 67,108,864 UTF-8 bytes, checks metadata before/after opening and bounds the read. This is an **unprivileged offline tool, not a hostile path-replacement/TOCTOU defense**; do not embed it in a privileged service as a path authorization boundary.

`source_revision` and `trace_digest` are deliberately null. A typed trace does not retain original input bytes and a caller's current Git HEAD/environment is not proof of the executable's source. The initial CLI does not supply authenticated build or raw-byte digest provenance. These local reports alone cannot satisfy a release gate. `kernel_runtime_tested` and `production_qualified` are always false. A mutant run can pass an unrelated trace; only a specific independent safety violation demonstrates that the fixture detected it.

## Independent components and retained state

| Component | Owns | Must not use as its oracle |
|---|---|---|
| Scheduler (`replay.rs`) | Input order, declared IDs, phase/failure precedence, decisions, terminal/abandoned counts | Wall clock, threads, hidden RNG |
| Fake lower (`replay/lower.rs`) | Actual volatile/durable origin, slot bytes, physical child samples/completions | Candidate visibility or cancellation as completion |
| Reference policy (`replay/policy.rs`) | Epoch/generation/incarnation tokens, reservations, publication, caller claims | Independent oracle decision helpers |
| Oracle (`oracle.rs`) | Independently applied/sampled histories, admission/bind/owner lineage, actual lease sets, expected immutable results | Candidate generation/valid bits or actual buffers copied as expected data |

Seed is recorded, not used to reorder events. Reads retain actual per-fragment samples, not a comparison with the latest origin at commit. Failed partial writes keep their real effects, even beyond the reported prefix. FUA/flush durability is checked separately from caller success; old persistence cannot regress newer durable history. Caller results and applied mutation histories survive parent retirement. Result guards compare the entire retained collection after every otherwise-successful nonassert event, including disappearance, extra entries, status/count/knownness/history changes and late children.

Cache write admission takes exclusive physical ownership and invalidates prior visibility immediately, even if it later fails. Cache reads hold shared leases to **actual completion**, and revalidate lineage at caller commit. Cancel and epoch invalidation never release physical leases. A stale fill may physically write but cannot publish; same-slot overwrites cannot resurrect an old content owner. Exhausted counters disable/retire caching without wrap; origin passthrough remains separate. Zero-length cache reads use the clarified half-open containing-line rule in [trace v1](../contracts/trace-v1.md), not an arithmetic `end - 1` shortcut.

Limits are 10,000 events, 1MiB origin, 1,024 live admitted parents and actual/reserved children each, and 16,777,216 reserved/owned logical data cells. Admission reserves mutation history and a child slot before later reads can consume them. Read-result reservations and retained history remain accounted after retirement. Each packed cell is at most 16 bytes; data is not a heap object per byte. Fixed origin/durable/slot arrays and the independently bounded oracle instrumentation are reported separately by `resource_usage()`. These are logical allocation bounds, **not RSS, nonpaged memory or production performance measurements**. Large boundary tests deliberately retain substantial host memory.
