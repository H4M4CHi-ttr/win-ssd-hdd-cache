### 実際に通過した検査

- SHA-256一致に加え、3つのMicrosoft NuGet packageのsignature verificationが成功。
- pure Rust core: debug **3/3**、release **3/3**。layout、8 literal vectors、51,200 bounded triplesを含む。
- PE precheck: **22 cases**。unsupported delay-import directoryもrejectする。
- 実MSVC C executable → 同じRust static library: **8 ABI vectors**成功。
- Rust WDM imageとC17 WDK shim imageのcompile/link、map/export確認、static PE検査が成功し、`D09_BUILD_ONLY_PROOF_COMPLETED`を記録。
- C kernel compileは `/WX /showIncludes`。job logの `warning Cxxxx` は **0件**。46件のkernel include表示はpinned kitまたはexperiment自身のheaderに限定され、MSVC `stdint.h`/`vcruntime.h`へのfallthroughなし。
- C mapはRust static libraryの `win_cache_probe_range`、`c-entry.obj` の `DriverEntry`、`BufferOverflowK` の `GsDriverEntry` を含む。

各試験・signature・include/warning検査の証拠は**Actions jobの完全なlog**である。artifactの `build-transcript.txt` はnative command出力の一部を含まず、完全なjob logの代替ではない。artifact単独で全試験を再確認できるとは主張しない。

## 受入範囲と残るgate

独立Astra reviewはlocal commit `56b184198bf43e3a595a1c80dbe32c19754e3b4d` のsource/evidenceをbuild-only scopeで**ACCEPT**した。source code/workflow/pinsはclean proofから不変で、4文書の追記を照合済み。最終GitHub更新・PR merge・Issue closeは未確認であり、artifactの技術受入とmain統合を区別する。

Rust-firstを維持し、WDK固有部分には小さいC escape hatchを残せる、というfeasibilityの根拠に限る。両entryはnullness確認以外にOS pointerへ触れず、常にfailureを返す。24byte returnのhidden caller-owned bufferはhost ABI試験で検査したが、async所有権、kernel panic、callback/IRQL、allocation/Drop、rundownは未実行。D01実trace・D04契約・D10のWindows所有権/故障注入mapping・署名/実機/公開gateは解除しない。
