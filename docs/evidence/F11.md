The late case deliberately gives the two children **different bytes**, so replacing an origin result with a late cache buffer is observable. No timeout event is invented: cancel is only a flag; completion remains a later explicit lower event. Result retention is checked before and after late transfer/completion by both fixture assertions and the oracle's independent post-event guard. This is the model's immutable-result/exactly-once contract, not proof about real asynchronous Windows notification.

Each reference has positive origin-result and ownership checks. Exact cache-lineage counts follow oracle §9.1's accepted publication/read-admission/cache-commit points; rejected claims do not invent checks. Durability remains not_observed, shadow not_applicable. All failure counts are zero for the reference, and strict evidence round-trip preserves LF output, null provenance and false qualification flags.

After every parent retires, the exact remaining owned data cells are shown above for **both** policy accounting and independent oracle accounting. Retained read results remain1/2 cells; the fallback case additionally retains its one-byte mutation history, hence2. Child/source buffers have drained but these required immutable records are not discarded to claim zero memory. Fixed media arrays are outside this counter by contract. This does not measure RSS, exercise real allocation failures or prove DMA quiescence.

## Precise mutant detection

The same cancel and epoch fixtures are also run with unchanged `late_slot_reuse`. They must stop at bind **8** and **7** respectively with `safety_violation/LIVE_LEASE_REUSED`, exactly one failed ownership check, zero executed fixture assertions and one still-pending physical child. The oracle detects the false bind claim; the harness does not fabricate actual completion to make the trace drain. Parser/assertion-only failure, panic or inconclusive are not acceptable mutant detection.
