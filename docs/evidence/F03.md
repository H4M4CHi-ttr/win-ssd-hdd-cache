# F03 — Deterministic completion queue

2026-11-02, Rust 1.99.1 x86_64-unknown-linux-gnu. Host-only model, not a device driver or DMA simulator.

Tests first: 6 integration tests failed at explicit `reserve` stubs, followed by 3 internal exhaustion/precedence tests failing for the same missing behavior. After implementation, all 9 passed; the full host suite then passed 20 tests. fmt and clippy passed.

```sh
cargo test -p cache-model --locked
cargo test --locked
cargo fmt --all -- --check
cargo clippy --all-targets --locked -- -D warnings
```

Verified cancellation is an idempotent flag, not completion: queue ownership and budget remain until explicit delivery. Reverse completion order, double-delivery/unknown-token refusal, non-reused monotonically increasing per-queue tokens, u64 exhaustion, and count/per-payload/total-byte limits are covered. Internal tests place the private counter at its limit without adding a public test-only API. Rejection leaves pending work unchanged. Returned Arc ownership remains valid after queue destruction.

This is a small deterministic building block for INV-05/09 tests, not proof that an Arc stops real DMA or that any Windows cancellation/rundown is correct. Queue identity is scoped to its own instance; tokens are not cross-process/global IDs. Windows host execution is pending F10. Device, kernel, signing and hardware tests were not run. Independent review/PR: Issue #7.
