## Actual host capacity measurement

Release test output for `exhausted_limits_never_drop_existing_io_and_measurements_are_explicit`:

```text
D03_HOST_MEMORY Memory { record_count: 4, reserved_cells: 49153, record_vec_capacity_bytes: 11264, owned_vec_capacity_bytes: 73731, fake_media_capacity_bytes: 32768, fixed_policy_bytes: 288 }
```

This sample is taken after one pending one-byte write and three admitted 8 KiB reads (including their future result reservations); the next such read is refused. The pending write then still completes and commits successfully. The fixture records the sample before that commit.

| Field | Interpretation |
|---|---|
| `record_count` | 4 live/retained records in this fixture, maximum 64 in the experiment |
| `reserved_cells` | 49,153 of 65,536 permitted logical cells; includes future caller-read copies not yet materialized |
| `record_vec_capacity_bytes` | 64 preallocated record slots × measured host layout; not just four live records |
| `owned_vec_capacity_bytes` | Current allocated payload, transfer coverage and retained result vector capacities |
| `fake_media_capacity_bytes` | RAM used by fake origin/SSD arrays; must not be extrapolated into a real driver design |
| `fixed_policy_bytes` | `size_of::<Experiment>()`, including inline vector handles, fixed line/slot state and counters |

Reported categories sum to **118,051 bytes** of these specific capacity/layout categories. They exclude allocator bookkeeping, stack, test binary/runtime, external caller input, fragmentation and unmaterialized reservations. This is not the process RSS, whole-run peak, a portable ABI size, a Windows nonpaged-pool budget or a statistically comparable OCF measurement. Debug and release use the same Rust layouts in the observed host setup, but other targets/toolchains must be measured independently.

The resource cap is logical and intentionally conservative. Actual `std` allocation can fail outside these checks and is not fault-injected. D04/B03 must provide fallible allocation, nonpaged telemetry and fail-safe admission behavior; no kernel OOM-recovery claim is made here.
