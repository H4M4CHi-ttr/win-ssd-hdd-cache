# ゲストCodexへの依頼　VM-A・T1の読み取り専用照会

この文書を所有者が指定ゲストのCodexに渡したときに使う。あなたの担当は**VM-AのゲストWindows内でのローカル照会と、匿名化した回答だけ**。P04はT1だけを対象とする実験用のディスクフィルターで、D01は保護対象のOSディスクである。登録、デバイス再始動、初回ロード、R1復元の実行はこの依頼に含まれない。

**通常は事前照会（PRE）だけを行う。** 事後照会（POST）は、所有者または指名された担当者が、別途承認した一括試行の発行後に、同じ試行番号・PRE記録・時刻範囲を添えてPOSTを指定した場合だけ行う。P04を見つけても自分でPREからPOSTに切り替えない。モード不明はPREとする。終了後はゲストを現状のまま返す。

### 入力と権限

- 作業前に、所有者の指定と既存の私的な照合記録で、このWindowsがVM-A自身だと確認する。普段使いのホスト、別VM、Windows以外、実行先未確定ならそこで止める。「VMware上のWindows」やbuildだけで同一VMとみなさない。
- 必要な入力は、今回の匿名試行番号、指定されたVM-A／D01／T1の私的照合記録、ホスト担当のVM-A・R1・両VMDK連鎖の照合結果。あれば、候補INF・CAT・SYSまたは審査済みの正確な照合条件とハッシュ、既設の実スタック証拠の参照も使う。生の値やパスをチャットに求めない。比較に使う資料は、所有者が指定したゲスト内の既存資料に限る。ホストの記録をゲストから確認した扱いにしない。VM-A自体は確認できても他の入力が欠ける場合は「未提示」として、できる照会を続ける。PREに試行番号がまだない場合は、その返信内だけの匿名名を使い、将来の試行との対応は未確定とする。
- 現在の通常権限と既存ツールだけを使う。この照会に所有者が別途明示した通常のUACがあればその範囲に限る。以前の別工程の許可を流用しない。自動昇格、権限拡大、AccessDeniedを別API・別資格情報で回避することは禁止。失敗した照会名、対象の匿名名、実際に返ったエラー種別・コード、不足が影響する判定を返す。
- プロパティ値、INF内容、イベント本文とコマンドの標準出力・エラーは、ゲスト内の同じローカル処理で捕捉して比較する。Codexのツール出力へ返すのは整形済みの集計だけ。シリアル、storage ID、hardware／compatible IDの実値、instance ID、個人名、絶対パス、ダンプや生ログをチャット・一時ファイル・外部サービスに出さない。IDの対応を説明するときだけ試行内のラベルを付ける。そのラベルは他の試行に持ち越さない。
- インストール・更新・署名、パッケージの追加／エクスポート、再スキャン、デバイスの無効化・有効化・再始動、サービスの起動・停止、レジストリ書込み、観測やCDO open、ダンプ・トレースの新規取得、ログの有効化は行わない。ディスクの初期化・マウント変更・format・lock・dismount・offline・raw I/Oを行わず、初期化ダイアログは受け入れない。ホスト、別マシン、VMwareやスナップショットは操作しない。

### 1　D01とT1を再同定する

1. 採取時刻、OSのbuildとアーキテクチャ、対象ディスクのpresent・started・問題コードを記録する。PREとPOSTではその都度列挙し直す。過去の `26300.9974` はAFTER_R1の記録である。
2. 既存の `Get-Disk`、`Get-Partition`、ローカルCIMなどの結果を私的に結び付ける。現在のOSとEFI/boot、すべての稼働中pagefile（`Win32_PageFileUsage` とその設定）、自動／小ダンプの保存先、専用ダンプファイル、休止およびほかの特殊用途の所在をディスクへ対応づける。設定値と実際の所在を区別し、不明なパスや欠けた照会を「不使用」にしない。必要ならD01内のpagefileの移動・割当・`TempPageFile` の差だけを報告する。
3. 指定された既存の私的記録と、完全なPnP instance ID、固有なストレージID・シリアル、親コントローラーの位置とLUNを照合する。D01とT1は一貫した別の記録に各1台ずつ一致すること。T1は8 GiB・RAW・区画0・特殊用途なしを確認する。ディスク番号・文字・容量・過去の匿名番号だけでは確定しない。ディスク自身の位置パスが空なら、その事実と親位置・LUNの取得状況を分ける。0件・重複・別世代・証拠矛盾なら本試行の個体対応は「未確定」とし、その名前で個体別の合格を出さない。

**PREで残すP04の開始状態。** 同じ採取窓で次の4項目を別々に確かめ、判定と根拠を返信に残す。既存の指定パッケージがなければ、既知のP04名との照合結果と「最終パッケージとの同一性は未提示」を分ける。

- **パッケージ。** ゲストの既存Driver Storeの第三者パッケージ一覧（例は `pnputil /enum-drivers`）をローカルで絞り、指定INFの版・発行元・ハッシュ、分かる範囲のカタログとの対応を確認する。デバイスに現在割り当てられたドライバーの一覧だけでは、配置済みパッケージの不在を確定しない。同名別物は衝突として返す。
- **サービスとselector。** 固定したP04サービス名（従来案は `WinSsdHddCacheProbeP04`）の登録・開始種別・状態・イメージの対応を、サービス設定とローカル `Win32_SystemDriver` 等の既存の読み取りで確かめる。指定サービスの `Parameters` にある `TargetInstanceId` のキー・値の有無、型、長さ、私的に同定したT1との完全一致を、存在する場合だけ読み取る。基準の未作成、値なし、残存、別物、読取不能を分ける。PREでは作成・修正しない。
- **ロード済みイメージ。** 所有者が認めた既設の読み取り元で、対象イメージが現在ゲストにロードされているかを照合する。根拠の種類、確認範囲と時点を返す。サービスがStopped／該当なし、ファイルが存在する、過去イベントに見当たらない、のいずれかだけで未ロードとしない。取得方法がなければ「未取得」とする。
- **残存参照。** 以下で調べるD01・T1・他の適用候補、クラスの上下フィルター、宣言的一覧および既存のvolume・dumpの基準に、P04への参照があるかを確認する。各範囲の一致数と未取得数を区別する。パッケージ・サービス・値・参照の残存、既ロード、同名競合を認めたPREは「開始条件不成立」。本件の効果を発行せず返答する。

### 2　拡張INFでD01を除外できるか

- まず `Get-PnpDevice -Class DiskDrive -PresentOnly` などの既存の列挙を使い、上の手順で同定したD01・T1それぞれの `DEVPKEY_Device_HardwareIds`、`DEVPKEY_Device_CompatibleIds` を全要素取得する。例は、私的に保持したIDを使う `Get-PnpDeviceProperty -InstanceId $privateId -KeyName 'DEVPKEY_Device_HardwareIds','DEVPKEY_Device_CompatibleIds'`。必要な読み取りには `pnputil /enum-devices /instanceid <私的ID> /deviceids /relations /services /stack /drivers` も使える。これらは照会の形を示す例で、生の出力をそのまま返さない。対応しないフラグや拒否は記録する。
- 候補の列挙子・クラスや参照INFを根拠に、T1以外に一致し得るVM-A内のdevnodeを特定する。親・兄弟、D01、該当し得る他クラス、接続中と既知の非接続・再登場候補も区別する。対象範囲の根拠が足りなければ、確認済みと未調査の範囲を分けて返す。比較に必要な場合だけ、既存PnP一覧から他候補の一致件数をゲスト内で集計する。余分な機器の実名やIDを出さない。
- **最終INFが未提示なら**、読み取れた範囲で「T1にあり、D01にも他の比較対象にも同じ文字列がないhardware／compatible ID」の件数または試行内ラベルを返す。両種類を横断して完全一致で比較し、大小文字以外の省略・部分一致で候補を作らない。一部未取得なら判定は暫定。これは肯定条件の候補探しであり、実パッケージのT1一致件数は「未評価」とする。共通IDがあるだけで、より狭い別の候補まで捨てない。
- **審査対象の最終INFが指定済みなら**、既存のローカル通常ファイルまたは版・ハッシュが一致する承認済み条件表だけを読む。実行・登録はしない。対象build/archで有効なManufacturer／Modelsの全行と追加ID、装飾、対応するDDInstall、直接指定のExcludeID、参照・付随INFの範囲を含め、Windowsの照合規則で適用先を評価する。仮の条件表や署名済みの実物との対応が取れない抜粋は「候補」であり、実パッケージの結果には数えない。未解決の参照、解釈不能な条件、未照合のファイルや対象があるなら「不明」。hardware ID／compatible IDだけをModels判定に使い、完全なinstance ID、LUN、シリアル、CHID、ExtensionIdを個体指定の代用にしない。T1に一致した有効行の件数、D01に一致した件数、他の対象外で一致したデバイス数、未評価数を別々に返す。これを将来の再接続後まで成立する証明にはしない。

### 3　配置の見込みと装着の事実を分ける

1. D01・T1のデバイス別とDiskDriveクラス別に、既存UpperFilters／LowerFiltersの取得状態、型・順序・重複を区別する。デバイスの `DEVPKEY_Device_UpperFilters` 等と、対応するクラスの `DEVPKEY_DeviceClass_UpperFilters` 等は別に扱う。読み取り可能なら `DEVPKEY_Device_CompoundUpperFilters`／`DEVPKEY_Device_CompoundLowerFilters` も別欄に取る。値なしを確定できた場合、正しい空列、値あり、未取得を混ぜない。volume・dumpについても既存の基準とP04名の新規参照の有無を、読めた範囲で記録する。
2. 各ディスクで実際に使われる基本ドライバーのサービスとINFを特定する。例は `DEVPKEY_Device_Service`、`DEVPKEY_Device_DriverInfPath`、`DEVPKEY_Device_DriverInfSection`、`DEVPKEY_Device_DriverInfSectionExt`、ドライバー版。既にある該当INFの有効節と必要な参照先を読んで、上位レベルの順序、`UpperFilterDefaultLevel`、既存の `partmgr` の登録元（デバイス／クラス／未特定）を確認する。候補の `FilterLevel` または `FilterPosition` が指定するレベル・位置、同レベルで順不同となる可能性を示す。適用節不明やレベルの未取得を「レベル定義なし」にしない。
3. `/stack` の**有効構成**は上から順に記す。共有済みの基準はD01・T1とも `partmgr → disk → stornvme`。別に登録されていた `EhStorClass` などを、表示上の実装着と混同しない。狙いはT1の `partmgr → P04 → disk → stornvme`、D01は元のまま。PREでは「位置を説明できる／説明できない」と根拠を返し、P04の実装着は「未試行」とする。PREで既にP04の登録・ロード痕跡を認めたら異常として止める。
4. **POSTだけ。** PREと独立に個体を再同定する。試行番号で、PREの未ロード証拠、署名済みパッケージとサービスの実体、承認後に保存済みのselector設定・読戻し記録を結ぶ。記録にある非空の完全なT1のIDが正しい型・長さで読めたこと、その読戻しが最初に有効化され得る操作より前だったこと、そこから初回ロードまで値・個体が保護されたことを照合する。共通の順序記録、または対応づけられた時刻と継続性の根拠を使う。現在値が同じ、時刻が近いというだけでは先行・保護成立にしない。指定された試行時刻に限って、既存のPnP・Code Integrity・サービス／イメージロード記録、登録情報と前後の構成を照合する。APIの発行・返答、T1の再始動と再開、指定イメージの初回ロード、D01や親のイベントを個別に記録する。イベントがないことから「0回」と結論しない。初回ロードには、PREで未ロードだったことと、同じ試行の時刻・固定SYSに結び付くロード証拠が要る。保存中のSYSの現在のハッシュだけでは、実際にロードされたイメージを確定しない。
5. POSTの実装着は、指定された既存の読み取り証拠が、今回の時点・正しいPDO・実際のデバイスオブジェクト列に対応する場合だけ評価する。その記録でT1の `disk` 直上、`partmgr` の直下にP04が1個、D01は0個で既存順を保持することを照合する。宣言的な合成一覧、PnPUtilの有効構成、サービスのRunning表示、CDO名の存在だけでは「実装着確認」にしない。D01・親・対象外への登録や再構成、クラス・volume・dumpの予期しない差分があれば、受入を中止して報告する。新規のデバッガ接続・ダンプ採取・CDOへのアクセスはしない。既存証拠がなければ「実装着未確認」と返す。

### 返信の形式

次の項目を短い表か箇条書きで返し、そこで終了する。「0件」は照会・範囲の両方が確認できたときだけ使う。取得できない値は「不明」、入力がない場合は「未提示」、実行前は「未試行」と書く。

1. **試行**　PRE／POST、匿名試行番号・採取時刻・build/arch、VM-Aの本人照合とホスト側R1・VMDK確認の有無。
2. **個体と用途**　D01・T1別の一意一致、親・LUNとの対応、OS/EFI/pagefile/dump/専用dump/休止、T1の容量・形式・区画数、前回からの差。
3. **INF照合**　実パッケージの提示・版一致、個体ごとのID配列の取得状態、T1のみの候補件数、最終INFの「T1一致行／D01一致行／その他一致デバイス／未評価」、比較範囲。機種を特定する文字列は返さない。
4. **位置**　D01・T1別の基本INF・版の一致、フィルター登録元・レベル、従来の上下列／宣言的一覧／上からの有効構成／実装着証拠の違い。PREは候補位置の見込み、POSTはT1の装着数・隣接、D01への影響・初回ロード・再始動の各結果。
5. **P04の事実**　PREはStore内の指定パッケージ／サービス／selector／ロード済みイメージ／各範囲の残存参照を、確認済みの不在・存在・同一性不明・未取得に分ける。POSTはこれに、PREでの未ロード、selectorの型・T1一致、読戻しと最初の有効化の順序、初回ロードまでの保護、固定SYSのロード、T1の再始動を付ける。ゲストで証明できない欄を根拠なしに補わない。
6. **停止判断**　「候補あり・審査待ち」「不一致／証拠不足で保留」「POSTのゲスト確認済み・観測未実施」「部分適用／影響不明・ホスト担当へ」のいずれかと、その理由。必須のPRE基準、selector先行・保護、対象限定、初回ロード、再始動、T1・D01の実装着位置のどれかが不明なら、POSTを確認済みにしない。権限不足などの実エラーと、判定に最低限必要な追加の読み取り項目を付ける。ゲストで再試行・修復・停止・復元を始めない。
