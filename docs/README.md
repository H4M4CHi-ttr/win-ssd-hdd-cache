文書の優先順位は **安全契約 → 採択済みADR → インターフェース契約 → Issue**。矛盾を発見したら実装で辻褄を合わせず、Issueに報告して設計を更新します。

## 状態の読み方

- **採択済み方針**: この計画の制約。実装・実機検証の完了を意味しません。
- **設計ゲート**: 選択・API・安全性の証拠を確定する課題。後続課題はゲートが閉じるまで着手しません。
- **planned path**: 将来作成するソース/テストの正確なパス。現時点で存在するという意味ではありません。
- **合格**: 指定した証拠、レビュー、環境の記録がそろった状態。Issueのcloseだけでは代用できません。

通常のパッケージ依存利用と、ソースvendoring/外部contributionの受付は区別します。ライセンス、公開範囲、証明書購入・署名主体は所有者の判断事項です。本計画はそれらを勝手に変更しません。
