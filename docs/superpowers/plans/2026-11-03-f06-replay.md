# F06 independent replay implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Implement Issue #20's deterministic, bounded host replay and independent oracle, including the three specified faulty candidates and strict evidence output.

**Architecture:** Root implements the accepted contracts, not a new product cache engine. Scheduler, actual fake-lower storage, reference policy, and independent history oracle are separate components. The oracle never reads reference generations/valid bits or calls its freshness helpers. Independent Astra review and two-OS CI precede F06 acceptance.

**Tech Stack:** Rust 1.99.1, edition2024, existing serde/serde_json; no new third-party dependency required. GUI, Windows APIs, raw devices, network and unsafe are outside scope.

**Spec:** [trace v1](../../contracts/trace-v1.md), [oracle v1](../../contracts/oracle-v1.md), [evidence schema](../../../spec/evidence-v1.schema.json), [accepted dependencies and CI](../../evidence/2026-11-03-phase2-integration.md).

## Global constraints and authorization

- D02/D07/F03/F04/F05 artifacts exist on the implementation base and have the required independent reviews and host CI. F06 is ready in the reviewed acceptance snapshot; its own completion remains pending.
- HDD is the only authority; this is clean read cache / Write-Invalidate, not write-back or persistent cache reuse.
- Event order is the trace array, seed is recorded only. No hidden RNG, thread or wall-clock dependency.
- 10,000 events, 1MiB origin, 1,024 live parents and children each, 16,777,216 reserved/owned logical data cells. Retained results and applied histories survive retirement. Cells use packed arrays with at most16 bytes per cell, not per-cell heap objects.
- Candidate resource accounting includes actual buffers and reservations; independent oracle instrumentation is bounded separately and its overhead is reported, never called nonpaged memory. Neither instrumented memory nor host success proves kernel suitability.
- One F06 PR. The evidence codec and module/dependency registrations are necessary integration changes within that issue, not unrelated features.
- User has delegated continued implementation and normal PR/CI/merge work. No new owner choice is required for these mechanical interfaces. License/signing/release/lab permissions remain unchanged.

Public `ReplayResult` has read-only accessors for evidence, decision history, caller results and final origin. Reports contain no payload. The typed result is not itself the public evidence JSON. `Fault` has only none/stale_fill/early_ack/late_slot_reuse. Source revision and trace digest stay explicitly null unless independently established; the initial CLI does not pretend that its current cwd or a reserialized trace establishes provenance.

## Review focus

- Accepted mutation without a forwarded child must reserve bookkeeping and block a preexisting flush frontier; a later read cannot consume that reservation. Test in Task3.
- A→B→A byte equality does not restore an old fill's lineage. Test in Task4.
- Caller completion does not terminate another pending cache child or release its physical lease; retained-result guard observes later transfer/completion. Test in Task4.
- Failed partial mutation can have effects beyond its reported prefix, survive retirement and later persist. Test in Task3.
- Input valid under JSON Schema can still have inconsistent counters/verdicts or disguised duplicate keys. Test in Task1.
