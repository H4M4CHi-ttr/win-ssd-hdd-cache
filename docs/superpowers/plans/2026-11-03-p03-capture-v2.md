# P03 Nullable-information Capture Audit v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Accept explicit v2 capture envelopes without discarding observed completions whose numeric Information is unknown, while preserving v1 behavior.

**Architecture:** Reuse the single strict typed parser and correlation algorithm in cache-types. A closed version selects only completion-information validation; a per-completion unknown bit adds the fifteenth fixed reason, and reports retain the input version. The existing offline CLI delegates to this API without new options or version guessing.

**Tech Stack:** Existing pinned Rust toolchain, serde and serde_json only; no new dependency, unsafe, OS/network/device access, or build workflow.

**Spec:** [P03 capture-envelope-v2](../../contracts/capture-envelope-v2.md), independently reviewed before publication; [P01 baseline](../../contracts/capture-envelope-v1.md).

## Global Constraints

- Limits remain **1,048,576 UTF-8 bytes** including whitespace and **4,096 records**.
- Required nullable completion Information is allowed only in explicit version2; completion status stays required nonnull u32.
- UNKNOWN_INFORMATION is appended after the existing fourteen reasons and is observed on all supplied completions, including duplicates.
- Preserve supplied order, counters and correlation; unknown Information is not event loss, zero, or a missing completion.
- Version1 report bytes and schema1 validation remain unchanged; only three documented unsupported-version witnesses move from2 to3.
- No P02 exporter, diagnostic projection, closure/target inference, new dependency, owner decision or D01/D04/D10/F08/F09/G1 change.
- P01 and P02 accepted artifacts plus publication of this independently reviewed contract must exist before any implementation, fixtures or code tests. P02 was accepted in PR85 after actual successful Windows build evidence; verify its evidence rather than infer completion from source presence.
- Minimum fixed-slice routing is agent:luna/review:astra. Root's v2 choice is an engineering selection under broad continuation authorization, not a user-specific v2 approval.

## Review Focus

- Null Information on a duplicate can disappear behind early return: core test `v2_unknown_information_survives_duplicate_orphan_and_target_mismatch` pins both duplicate orders.
- A missing required field can be treated like explicit null: core `v2_required_presence_and_escaped_duplicates_are_strict` and CLI `v2_missing_information_is_not_a_nullable_field` reject omission.
- A v1 null can be silently upgraded to v2: core `v1_null_information_and_golden_bytes_remain_frozen` and CLI `v1_null_information_is_not_upgraded` preserve rejection.
- Unknown metadata can be miscounted as actual missing events: core `v2_unknown_information_and_actual_loss_are_independent` keeps exact ordinals/counts/reasons.
- Plausible boundary/provenance fields can become inferred authority: core `v2_boundary_range_and_provenance_uncertainties_keep_order` plus literal report tests retain explicit uncertainty and all four false flags.
